# Claude VPN Guard

Не даёт открыть Claude (приложение, claude.ai, anthropic.com, Claude Code) без включённого VPN.
Нужно, чтобы случайно не зайти в Claude напрямую.

| Платформа | Как блокирует |
|---|---|
| **Linux (systemd)** | Фаервол nftables отклоняет соединения к серверам Anthropic, если они идут не через VPN-интерфейс. Пока VPN выключен, домены Claude ещё и заглушаются в `/etc/hosts`, чтобы DNS-запросы не уходили провайдеру. |
| **Android 15–16** | Значок «Claude (VPN)»: открывает Claude, только если включён VPN и интернет идёт из страны, где Claude доступен. Дополнительно — «VPN-блокировщик»: пока ваш VPN выключен, к серверам Anthropic не уходит ни одного пакета. |
| **Chrome на компьютере** (и Яндекс Браузер, Edge, Brave, Vivaldi) | Расширение: пускает на claude.ai / anthropic.com, только если интернет идёт из страны, где Claude официально доступен. Из России, Беларуси, Китая, Ирана и др. — блокирует все запросы до отправки. |

## Linux

Нужны `nftables`, `iproute2` и systemd.

**Arch Linux** — готовый пакет из Releases:

```bash
sudo pacman -U claude-vpn-guard-*-any.pkg.tar.zst
```

или собрать из клона репозитория:

```bash
cd linux && makepkg -si
```

Служба включается сама при установке. `pacman -R claude-vpn-guard` снимает блокировку и удаляет всё.

**Debian / Ubuntu:**

```bash
sudo apt install ./claude-vpn-guard_*.deb
```

**Любой дистрибутив:**

```bash
tar xzf claude-vpn-guard-linux.tar.gz && sudo ./install.sh
```

(или из клона репозитория: `sudo linux/install.sh`)

Проверка:

```bash
claude-vpn-guard status
```

```
Маршрут к Claude (160.79.104.10): wlan0
VPN:        НЕ АКТИВЕН — Claude заблокирован
nftables:   правила загружены
/etc/hosts: заглушки доменов Claude включены
Служба:     active
```

### Как это устроено

- Служба `claude-vpn-guard.service` загружает таблицу `inet claude_vpn_guard`. В ней трафик к сетям
  Anthropic (`160.79.104.0/23`, `2607:6bc0::/48`) и к текущим IP доменов Claude разрешён **только**
  через интерфейсы VPN (`tun*`, `wg*`, `ppp*`, `tailscale*`, `nekoray*`, `sing-box*`, …).
  Через `eth0` / `wlan0` соединение сразу отклоняется.
- Это работает для любого браузера (включая DNS-over-HTTPS и QUIC), для Claude Code в терминале и для
  Docker-контейнеров.
- `nftables.service` в Arch при запуске делает `flush ruleset` — служба это замечает и за ~3 секунды
  возвращает свои правила.
- Split tunneling тоже учтён: если VPN включён, но Claude в него не заворачивается, Claude будет заблокирован.
- Раз в 3 секунды служба проверяет, через какой интерфейс идёт маршрут к Claude, и включает/выключает
  заглушки в `/etc/hosts`. Если правила кто-то сбросит (например, `nft flush ruleset`), они восстановятся.
- При смене состояния на рабочий стол приходит уведомление (нужен `notify-send`).
- Если процесс упадёт, systemd перезапустит его через 2 секунды. При остановке службы
  (`claude-vpn-guard off`, `systemctl stop`) правила и заглушки снимаются.

### Claude Code в терминале

Claude Code обращается к `api.anthropic.com`, `claude.ai` и `platform.claude.com` (вход), — все они
находятся в сети Anthropic `160.79.104.0/23`, поэтому без VPN он не подключится. Плюс в `/etc/hosts`
заглушаются `downloads.claude.ai` (обновления), `mcp-proxy.anthropic.com` и адреса телеметрии Datadog,
чтобы и они не уходили мимо VPN.

Проверено на настоящем Claude Code 2.1 в тестовой сети с «провайдером» (`wlan0`) и «VPN» (`wg0`):

| Режим | Что произошло |
|---|---|
| VPN выключен | все 31 попытка соединения отклонены фаерволом, до сервера не дошло ни одной |
| VPN выключен + заглушки hosts | `api.anthropic.com` → `::`, до сервера не дошло ни одной |
| VPN включён | соединения пошли через `wg0` и дошли до сервера |

Без VPN Claude Code не выдаёт ошибку сразу: он какое-то время переподключается, а потом пишет
`Unable to connect to API`. Если Claude Code настроен на Amazon Bedrock или Google Vertex, а не на API
Anthropic, эти адреса не блокируются.

### Включить / выключить

```bash
sudo claude-vpn-guard off
```

Полностью выключает защиту: останавливает службу, убирает её из автозапуска, снимает правила фаервола
и заглушки в `/etc/hosts`. Включить обратно:

```bash
sudo claude-vpn-guard on
```

(`systemctl disable` без `--now` только убирает автозапуск, а уже запущенная служба продолжает работать —
поэтому лучше пользоваться `off`. Эквивалент: `sudo systemctl disable --now claude-vpn-guard`.)

### Какой VPN считается включённым

- **Любой TUN- или WireGuard-интерфейс**, как бы он ни назывался: Hysteria2 в режиме TUN, sing-box, xray,
  v2rayN, Nekoray/Throne, Hiddify, OpenVPN, WireGuard, AmneziaWG и т. д. Проверяется тип интерфейса
  (`/sys/class/net/*/type` = 65534), а не имя. Также PPP (L2TP/PPTP) и интерфейсы из `VPN_IFACES`.
- **Прокси-режим без TUN** (Hysteria2, sing-box, xray и др. как SOCKS5/HTTP-прокси): пока процесс клиента
  запущен, заглушки в `/etc/hosts` снимаются. Фаервол при этом остаётся: через прокси Claude работает
  (к Anthropic подключается сервер прокси), а приложения, которые ходят напрямую, по-прежнему блокируются.
  Для Claude Code в этом режиме задайте прокси, например `export HTTPS_PROXY=http://127.0.0.1:8080`
  (адрес — из конфига вашего клиента).

`claude-vpn-guard status` показывает, через какой интерфейс идёт маршрут к Claude и какие интерфейсы
считаются VPN:

```
Маршрут к Claude (160.79.104.10): hytun
VPN:        АКТИВЕН (интерфейс hytun) — Claude доступен
...
Интерфейсы:
  hytun            type=65534  VPN
  wlp2s0           type=1      -
```

### Настройка

Файл `/etc/claude-vpn-guard/config` (после изменения — `sudo systemctl restart claude-vpn-guard`).
Если VPN включён, а `status` пишет «НЕ АКТИВЕН», посмотрите строку «Маршрут к Claude»: если там ваш
обычный интерфейс (`wlp*`, `enp*`), значит VPN не заворачивает трафик к Claude (split tunneling или
прокси-режим). Если клиента нет в `PROXY_PROCESSES`, добавьте имя его процесса туда.

Удалить: `sudo pacman -R claude-vpn-guard`, `sudo apt remove claude-vpn-guard` или `sudo ./uninstall.sh`.

## Chrome (расширение)

Работает в Chrome, Chromium, Яндекс Браузере, Edge, Brave, Vivaldi **на компьютере** (Linux, Windows,
macOS).

**На телефоне расширение не поставить:** Chrome для Android не поддерживает расширения вообще. На телефоне
браузеры закрывает Android-приложение — его «VPN-блокировщик» не пускает к серверам Anthropic из любого
браузера, пока VPN выключен (см. раздел «Android» ниже).

### Установка

1. Скачайте `claude-vpn-guard-chrome.zip` из Releases и распакуйте в постоянную папку (не удаляйте её потом).
2. Откройте `chrome://extensions`, включите **Режим разработчика** (справа вверху).
3. **Загрузить распакованное расширение** → выберите распакованную папку.
4. Закрепите значок расширения на панели: на нём видно `VPN` (зелёный — можно) или `✕` (красный — заблокировано).

### Как работает

Браузер не может узнать, включён ли VPN в системе, поэтому расширение проверяет, **из какой страны вы выходите
в интернет** (Cloudflare `/cdn-cgi/trace`, к Claude не обращается):

- страна в [официальном списке](https://www.anthropic.com/supported-countries), где Claude доступен
  (185 стран + их территории) → Claude открывается;
- любая другая страна (Россия, Беларусь, Китай, Гонконг, Иран, КНДР, Сирия, Куба, Венесуэла, Афганистан,
  Мьянма…), или проверить не удалось → все запросы к `claude.ai`, `claude.com`, `anthropic.com`,
  `claudeusercontent.com`, `claude.site` отклоняются **до отправки** (API, WebSocket, картинки — тоже),
  а вкладки с Claude показывают «Claude заблокирован — включите VPN»;
- как только VPN заработает, страница сама вернётся в Claude (проверка каждые 3 секунды).

Пока открыт Claude, подключение перепроверяется каждые 10 секунд, в остальное время — раз в 30 секунд.
При запуске браузера, до первой проверки, Claude заблокирован.

Проверено в headless Chromium: при стране RU вкладка claude.ai уходит на страницу блокировки, запрос к
`api.anthropic.com` с другого сайта отклоняется; при DE блокировка снимается и вкладка возвращается в Claude;
при смене на CN с открытым Claude — блокировка за ≤10 секунд; если сервер проверки не отвечает — блокировка.

### Настройки

Правый клик по значку → **Параметры**:

- **Дополнительно запретить страны** — например, вашу, если Claude в ней доступен, но вы хотите заходить
  только через VPN.
- **Где проверять страну** — если VPN пускает через себя не весь трафик (раздельное туннелирование по
  доменам), укажите адрес, который точно идёт через VPN. Ответ должен быть в формате `cdn-cgi/trace`
  (строка `loc=XX`) — подойдёт `/cdn-cgi/trace` любого сайта на Cloudflare.

Ограничение: если в VPN-клиенте `cloudflare.com` идёт напрямую, а `claude.ai` — через VPN (или наоборот),
расширение увидит не ту страну. С обычными правилами «российские сайты напрямую, остальное через VPN»
оба адреса идут через VPN.

## Android

Сборка только под свежие Android: **15 и 16** (minSdk 35, targetSdk 36). На более старых версиях APK не
установится. Если нужен Android 14, поменяйте `minSdk = 35` на `34` в `android/app/build.gradle.kts`.

### Значок «Claude (VPN)» — главный способ

После установки на рабочем столе появляется значок **Claude (VPN)**. Открывайте Claude только через него
(значок самого Claude лучше убрать с рабочего стола):

1. VPN выключен → экран «VPN не включён» и кнопка «Открыть VPN». Как только VPN подключится — вернитесь
   в приложение, Claude откроется сам.
2. VPN включён → приложение узнаёт через Cloudflare (`/cdn-cgi/trace`, к Claude не обращается), из какой
   страны идёт интернет. Если это страна, где Claude официально доступен, — открывает Claude. Если нет
   (VPN-сервер в России, Беларуси, Китае… или Claude идёт мимо VPN) — пишет, из какой страны вы выходите,
   и просит сменить сервер.
3. Нет ответа от проверки → Claude не открывается, есть кнопка «Проверить снова».

Настройки — долгое нажатие на значок → «Настройки» (или кнопка на экране). Проверку страны можно выключить.

Список стран — официальный [Supported Regions Policy](https://www.anthropic.com/supported-countries)
Anthropic (185 стран + их территории). Одно ограничение: в Украине не поддерживаются Крым, Донецкая,
Луганская, Херсонская и Запорожская области, а по стране подключения их не отличить.

### Какой APK ставить

| Файл | Что делает |
|---|---|
| `claude-vpn-guard-android.apk` | **Рекомендуется.** Значок «Claude (VPN)» + сетевая блокировка. Не использует спец. возможности, поэтому Play Protect к нему не придирается |
| `claude-vpn-guard-android-full.apk` | То же + если открыть Claude напрямую без VPN, показывает экран «Claude заблокирован». Работает через службу спец. возможностей — Google Play Protect блокирует такие приложения не из Play Маркета |

Ставится что-то одно. Чтобы сменить вариант, сначала удалите установленный.

### Установка

1. Скачайте `claude-vpn-guard-android.apk` и установите (разрешите установку из браузера/файлового менеджера).
   Если Play Protect покажет предупреждение — нажмите **Подробнее → Всё равно установить**.
2. Дальше открывайте Claude через значок **Claude (VPN)**. Этого уже достаточно.

Дополнительно (рекомендуется) — сетевая блокировка, на случай если Claude откроется напрямую:

3. **Выключите свой VPN** (Happ, Hiddify, v2rayNG…), откройте настройки (долгое нажатие на значок →
   «Настройки»), включите
   **Блокировать сеть (VPN-блокировщик)** и разрешите VPN-подключение. Если сделать это при включённом VPN,
   Android один раз отключит его — так система выдаёт разрешение на VPN. Дальше блокировщик сам уступает
   место вашему VPN и больше его не отключает.
4. Разрешите уведомления: в шторке будет видно, заблокирован ли сейчас Claude.
5. Нажмите **Выбрать VPN-приложение** и выберите свой VPN — кнопка «Открыть VPN» будет сразу запускать его.

Дальше всё работает в фоне само (и после перезагрузки), открывать приложение не нужно.

Для полной версии дополнительно: **Включить службу** → «Скачанные приложения» → **Claude VPN Guard** →
включить. Если переключатель серый («Ограниченная настройка»): **О приложении** → **⋮** →
**Разрешить ограниченные настройки** и повторить.

### Если Play Protect всё равно блокирует

- При установке: **Подробнее → Всё равно установить** (или «Установить без проверки»).
- Если приложение уже установлено и Play Protect его отключил: Play Маркет → значок профиля →
  **Play Защита** → ⚙ → выключить **Проверять приложения с помощью Play Защиты**, установить APK заново,
  после этого проверку можно включить обратно (в уведомлении о приложении выберите «Не блокировать»).
- Чаще всего Play Protect срабатывает на службу спец. возможностей — поэтому основной APK без неё.

### Как работает сетевая блокировка

На Android одновременно может работать только один VPN. Приложение пользуется этим:

| Ваш VPN | Что происходит |
|---|---|
| выключен | приложение поднимает свой VPN-блокировщик (в строке состояния значок ключа). В него направлены только адреса Anthropic (`160.79.104.0/23`, `2607:6bc0::/48` и текущие IP `claude.ai`, `api.anthropic.com` …). Пакеты туда никто не отправляет дальше — они отбрасываются на телефоне. Весь остальной трафик идёт мимо, как обычно |
| включаете | ваш VPN-клиент забирает VPN-слот, Android сам отключает блокировщик, трафик Claude идёт через ваш VPN |
| выключаете / отвалился | через ~1,5 с блокировщик снова поднимается |

Блокировщик — фоновая служба с уведомлением в шторке («VPN выключен — Claude заблокирован» / «Ваш VPN
включён — Claude доступен»). Она сама запускается после перезагрузки и после обновления приложения.

В полной версии служба специальных возможностей ещё и следит за экраном: если без VPN открыть приложение
Claude или `claude.ai` / `claude.com` / `anthropic.com` в любом браузере, — уводит на домашний экран и
показывает «Claude заблокирован» с кнопкой «Открыть VPN».

По умолчанию блокировщик действует только на приложение Claude и браузеры, поэтому остальные приложения
(например, банки, которые не работают с VPN) его не видят. Переключатель «для всех приложений» закрывает
Anthropic для всего телефона.

### Ограничения

Есть два коротких момента, когда защиты сети нет:

- ~1,5 с после того, как ваш VPN выключился или отвалился (пауза нужна, чтобы не мешать VPN, который
  просто переподключается);
- до 20 с, пока ваш VPN-клиент подключается после того, как вытеснил блокировщик. Если за 20 с VPN так и
  не подключился, блокировщик возвращается.

Ещё:

- Если у вашего VPN в настройках Android включён **«Постоянный VPN»**, блокировщик подняться не сможет.
  Тогда включите там же **«Блокировать подключения без VPN»**: Android сам не выпустит никакой трафик без
  VPN (но и весь остальной интернет без VPN пропадёт).
- Сразу после включения телефона, пока служба не запустилась (несколько секунд после разблокировки),
  защиты сети нет.
- Некоторые прошивки (Xiaomi, Huawei, Samsung) агрессивно убивают фоновые службы — если уведомление
  пропадает, разрешите приложению работу в фоне / отключите для него оптимизацию батареи.
- Сам DNS-запрос «где claude.ai» уходит вашему DNS-провайдеру (не в Anthropic), блокируется только соединение.
- Локальные «VPN» вроде AdGuard, RethinkDNS или Blokada занимают VPN-слот — с ними блокировщик не работает,
  а приложение считает, что VPN включён.

### Подпись APK

Без настроенных секретов GitHub Actions подписывает APK временным debug-ключом, который меняется при каждой
сборке, — поэтому для обновления придётся удалить старую версию. Чтобы обновления ставились поверх,
создайте свой ключ:

```bash
keytool -genkeypair -v -keystore release.jks -alias guard -keyalg RSA -keysize 4096 -validity 36500
```

и добавьте в **Settings → Secrets and variables → Actions** репозитория секреты:
`KEYSTORE_BASE64` (вывод `base64 -w0 release.jks`), `KEYSTORE_PASSWORD`, `KEY_ALIAS` (`guard`),
`KEY_PASSWORD`.

### Сборка вручную

Нужны JDK 17+ и Android SDK с платформой 36:

```bash
cd android && ./gradlew assembleRelease
```

APK: `android/app/build/outputs/apk/vpn/release/app-vpn-release.apk` (основной) и
`android/app/build/outputs/apk/full/release/app-full-release.apk` (полная версия).
